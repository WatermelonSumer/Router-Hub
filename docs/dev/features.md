# Router-Hub 功能总结文档

> AI 中转站 Rank 系统 —— 完整功能与决策记录
> 用途:回忆「做了什么 + 为什么这么定 + 刻意不做什么」
> 最后更新:2026-06-28
> 配套技术蓝图见同目录 `blueprint.md`

---

## 0. 一句话定位

一个**带客观探测征信的 AI 中转站排行榜 + 避雷坟场 + 站长批发撮合市场**。
普通用户来挑靠谱的中转站,站长来上架拉客、并在内部市场互相倒卖 API 产能。

本质上是**两个产品叠在一起**:
- **C 端**:普通用户挑站(rank + 坟场 + 详情页 + 评价)—— 对外开放、吃 SEO 流量。
- **B 端**:站长之间批发倒卖产能(站长广场)—— 登录墙后封闭、保护底价。
- 站长是**双重身份**:既是被 rank 排名的「对象」,又是广场里的「交易参与者」。

---

## 1. 核心价值与护城河

中转圈的供需对接现在已经在 TG/QQ 群里发生,排行也有人零散在做。**凭什么用户和站长来用 Router-Hub?**

护城河 = **客观探测产生的、可验证的信誉**。
- 群里喊单的人匿名、无历史、无法核实。
- Router-Hub 里每个站点/站长都背着一份客观探测履历(综合分、存活时长、坟场记录)。
- 广场不是聊天室,而是「**带征信的批发市场**」。
- 评价不是谁都能发,而是「**真实交互(充值/对接)才解锁**」。

**所有功能都围绕这条护城河展开。脱离「可验证信誉」的功能都是噪音。**

## 2. 三类角色与权限

| 角色 | 定义 | 能做什么 |
|---|---|---|
| 游客 | 未登录 | 只看 rank 榜单、坟场、详情页**基础信息+在线率** |
| 用户 user | 登录,role=user | + 详情页硬信息(延迟/价格/地址)、+ 充值验证后评价 |
| 站长 owner(未验证) | 登录,role=owner,但没有通过探测的真站 | 同 user + 可上架站点;**进不了广场** |
| 站长 owner(已验证) | 成功上架并通过探测**≥1 个真实站点** | + 自己站探测看板、+ **完整广场权限** |

**关键决策:**
- 「游客」不是登录角色,是「未登录」状态。
- **站长进广场的门槛 = 必须有一个通过探测的真实站点。** 理由:挡住没有真站的骗子和打探底价的人,让广场每个人都带可验证履历。这是把 C 端探测能力直接变成 B 端准入门槛。
- 广场门槛设在「**查看**」而非「发帖」—— 因为要避免普通用户/游客看到批发底价。
- 站长注册**必填微信 + QQ**,但联系方式**默认隐藏**,只在双方对接 confirmed 后作为「名片」交换。必填是为了平台可触达,不等于公开展示(防批量采集)。

## 3. Rank 排行榜

### 3.1 三个分榜(MVP)
- Claude 专用榜 / GPT 专用榜 / Gemini 专用榜。
- 实现上**不写死**,而是「模型族筛选 + 排序键」的查询:维度=模型族,排序=综合分/速度/在线率/价格。
- 前端 = 顶部三个 Tab + 一行排序切换。将来加「Grok 榜」「最便宜榜」只改配置。

### 3.2 综合分构成(四指标)
| 指标 | 来源 | 权重取向 |
|---|---|---|
| 在线率(稳定性) | 高频存活探测,时间加权(近期>历史) | 用户最在乎(跑路恐惧量化) |
| 速度分 | 低频质量探测真实 TTFB,用中位数/P90 | —— |
| 真实性/可用性 | 质量探测,MVP 只做 0/1 | **权重要高**,假模型必须狠扣 |
| 用户评价分 | C 端充值验证评价 | **权重低 ≤10%**,仅参考 |

### 3.3 三榜权重不同(重要,常被忽略)
- **Claude 榜**:用户多为编程/Agent 重度用户,最怕降智 → **真实性权重高**。
- **GPT 榜**:用户量大、价格敏感 → 价格/在线率权重高。
- **Gemini 榜**:可用性波动大 → 在线率权重高。
- 表结构支持「每榜一套权重」(`leaderboard_weights`),不是全局一套。

### 3.4 三个翻车点的处理
1. **探测抖动**:单次失败 ≠ 有问题。状态变更需连续 N 次确认;分数用滑动窗口平滑,不被单次探测带跳。
2. **新站冷启动 → 方案 C(隔离观察区)**:新站不进主榜,先进「新站观察区/试用榜」,标注「数据积累中,7 天后入主榜」,攒够样本再入主榜。既不污染主榜、又给曝光、又防刷(刷只能刷观察区)。
   - (放弃的方案 A 乐观冷启动=易刷榜;方案 B 悲观冷启动=站长体验差不愿来)
3. **老站躺赢/榜单僵化**:近期表现权重 > 历史累积,老站变差会掉、新站变好能升。靠时间衰减实现,不需复杂算法。

### 3.5 四指标归一化(各算法不同,均 0-100,详见 blueprint「六之二」)
- **在线率**:时间衰减加权(半衰期 7 天,`.env` 可调),非简单比例;维护窗探测剔除。
- **速度**:质量探测 TTFB 的 **P90**(非均值)→ 锚点分段映射(1500ms 满分,中转站多跳故起点高;拐点/分数在 `.env`)。非线性,快区间分得细。
- **真实性**:最近 20 次质量探测的成功比例 ×100(非单次,防限流误判)。
- **评价**:贝叶斯平均(IMDb 同款),评价少时被全站先验稀释,防"1 条 5 星刷榜";仅 verified 计入,权重 ≤10%。
- **缺失数据 → 动态权重重分配**(不补 0):某指标无数据时其权重摊给有数据指标 → 冷启动公平的数学保证。
- 全部归一化参数 `.env` 可配:`UPTIME_HALFLIFE_DAYS`/`SPEED_ANCHORS_MS`/`SPEED_ANCHORS_SCORE`/`AUTHENTICITY_WINDOW`/`REVIEW_BAYESIAN_C`。

## 4. 站点详情页

用户决策的核心页面,也是站长门面,信息密度决定 rank 的公信力。分三屏区:

**顶部「信任卡」**(游客可见):存活时长 + 在线率 + 跑路风险灯。
**中部「性能区」**(部分锁登录):延迟曲线 + 模型清单 + 真伪标记。
**底部「决策区」**(锁登录):价格 + 起充门槛 + 评价 + 跳转按钮。

### 完整字段清单
| 字段 | 说明 | 游客可见? |
|---|---|---|
| 历史在线率曲线 | 过去 30 天,暴露宕机/波动历史(比干净快照更可信) | ✅ |
| 站点存活时长/上架时间 | 「活了多久」是跑路风险最直觉信号,零成本高价值 | ✅ |
| 跑路风险提示 | 状态灯(正常/异常/疑似/阵亡) | ✅ |
| 最近探测时间戳 | 「3 分钟前探测」= 数据是活的,本身就是公信力 | ✅ |
| 支持的模型清单 | 探测到的真实模型列表 | ✅ |
| 真伪/可用性标记 | MVP 仅「已验证可用✓」(真打通 chat 拿到合理回复) | ✅(基础) |
| 实测延迟 | TTFB | ❌ 锁登录 |
| 价格/倍率 | | ❌ 锁登录 |
| 起充门槛 + 支付方式 | 最低充多少、支持什么支付 | ❌ 锁登录 |
| 限速/并发 RPM | 实际能不能用的关键,常被藏 | ❌ 锁登录 |
| 站点地址/跳转 | | ❌ 锁登录 |

> 游客部分可见的设计:既保住 SEO 流量入口(搜进来能看到基础信息),又用硬信息做注册转化钩子。

## 5. 中转站坟场(传播引爆点)

**为什么比 rank 本身更有传播力:** rank 是「帮人选」,坟场是「帮人避雷 + 看热闹」,情绪强度和分享欲高得多。「XX 站跑路了」是会被截图发群的内容。

### 设计要点
- **分级状态,绝不一刀切**:`正常 → 异常(连续失败 N 小时)→ 疑似跑路(失败 >X 天)→ 确认阵亡(失败 >Y 天/社群确认)`。不要一宕机就打「跑路」,防误伤 + 防法律纠纷。
- **保留「生还」状态**:站点恢复能移回,但保留「曾阵亡 X 天」污点。
- **坟场页是 SEO 富矿**:「xx中转站 跑路」高频搜索词,每个阵亡站一个详情页吃流量。
- **法律措辞**:用客观探测事实(「连续 X 天探测失败」),不用主观定性(「该站骗钱」),保护平台自己。
- 判定与触发探测联动:存活探测发现连续失败 → 触发质量探测插队确认 → 加速且精准判定。

## 6. 探测系统(技术核心)

### 6.1 探测的三个难度档位
1. **存活+模型列表探测**(便宜·低风险):打 `/v1/models`,看在线、看模型列表。**MVP 主力。**
2. **真实可用性探测**(烧钱·需 key):用站长 key 打 `/v1/chat`,测 TTFB、测真实性。**MVP 做,但 0/1 级别。**
3. **真伪/降智检测**(最难·最强壁垒):判断是否偷换便宜模型/限流降质。**留长期,先在数据模型留位置。**

### 6.2 分层探测(省钱 + 实时性平衡)—— 已定稿
| 层 | 频率 | 成本 | 作用 |
|---|---|---|---|
| 存活探测 | 3–5 分钟 | 几乎免费 | 撑「实时感」+ 宕机预警 |
| 质量探测 | 30–60 分钟 | 烧站长 key 的钱 | 真实速度/可用性,配合站长每日预算上限 |
| 触发探测 | 异常时插队 | 仅异常时 | 快速判定真宕机 vs 误报,加速坟场判定 |

- worker = 独立进程,APScheduler 起三个不同周期 job,httpx 并发。MVP 不上 Celery。
- 质量探测每次发最短 prompt(max_tokens=1),站长可设每日预算上限,超额自动降频,避免烧爆 key 引纠纷。

### 6.3 key 安全(头等大事)
- 站长入驻填 base_url + key,平台拿 key 发真实付费探测。
- key **加密落库**(Fernet/AES-GCM),密钥走环境变量,**绝不进代码库/日志**。
- key **永不下发前端**,站长本人只见掩码 `sk-***1234`。
- 所有用 key 的动作只在后端 worker 内发生。
- 明确告知站长「平台会用你的 key 发起计费探测」+ 频率说明。

### 6.4 防作弊(低成本措施)
- 探测不用固定 UA/IP/prompt,留随机性,抬高「给探测开小灶」门槛。成本几乎为零。
- 长期战场:识别站长是否对探测请求降智优待,真实用户来了才降质。MVP 不做,留长期。

## 7. 用户评价(C 端)

### 7.1 资格:必须「充过值」才能评(防水军)—— 方案 B
**用 new-api/sub2api 的 key 自证消费**(最优雅,复用探测能力):
- 用户评价前,用他在该站的 key 做绑定。
- 平台后端拿这个 key 调该站的额度/用量查询接口。
- 查到有消费/余额 → 证明真实付费用户,**无需上传任何截图,难造假**。
- (放弃方案 A 截图审核=能 PS、要人力;方案 C 导流闭环=暂未做交易)

### 7.2 定位
- 评价**为辅,不进综合分主干**(或权重 ≤10%),详情页展示并标注「主观评价」。
- 只有 verified(已验证充值)评价才计入加权,未验证标灰。
- 注意:new-api 不同版本额度查询接口路径可能不一,落地需适配。

## 8. 站长广场(B 端批发市场)

### 8.1 定位
站长之间批发倒卖 API 产能:**找上游=进货,找下游=出货**。
0.05 倍率、200rpm 这些是批发黑话。例:「找 200rpm 的 claude 上游」「0.05 倍率出售 gpt 下游」。

### 8.2 核心设计原则:结构化,不是聊天室
做成自由文本留言板 = 退化成又一个群聊,失去相对 TG 群的唯一优势(可筛选可匹配)。
**帖子是结构化的:**

| 字段 | 说明 |
|---|---|
| 类型 | 供给(出货)/ 需求(进货) |
| 方向 | 上游 / 下游 |
| 模型族 | claude / gpt / gemini |
| 倍率 | |
| rpm/并发 | |
| 量级 | 日均调用量/额度规模 |
| 结算方式 | 日结/周结/预付 |
| 补充说明 | 唯一的自由文本 |
| 联系方式 | 默认隐藏,对接后交换 |

供给帖和需求帖是对称两面,共用一套字段。可按字段筛选(「所有 0.05 倍率以下的 gpt 供给帖」)—— 这才是市场,不是群聊。

### 8.3 对接/报名机制
- MVP 不做站内私信(重)。看到合适帖子点「对接/报名」→ 系统通知发帖人「有人对接 + 对方站点履历 + 联系方式」。
- 双方交换的是「**带探测履历的名片**」,不是裸联系方式。
- 流程:发帖 → 对接(pending)→ 双方确认(confirmed)→ 交换微信/QQ + 解锁互评权。

### 8.4 可见性:刻意封闭(与 rank/坟场相反)
- 整个广场在登录墙后,**刻意不被 SEO 收录**,保护批发底价不外泄。
- rank/坟场 = 尽量曝光吃流量;广场 = 尽量封闭保底价。两套相反的可见性策略。

### 8.5 命名(已定稿):中转集市
正式名 **「中转集市」**。"集市"传达买卖撮合的烟火气,贴合站长批发倒卖产能的定位。
(曾备选:中转码头 / 产能交易所 / 供需大厅 / 倍率江湖)

## 9. 信誉与评价体系(两类评价)

| | C 端用户评价 | B 端站长互评 |
|---|---|---|
| 谁能评 | 登录用户 | 已验证站长 |
| 解锁条件 | 在该站**充过值**(key 自证) | 在广场**对接 confirmed** 过 |
| review_type | user_topup | owner_deal |
| 展示标注 | 「来自用户(已充值✓)」 | 「来自交易对手(已对接✓)」 |

**B 端信誉沿用 C 端**(站长广场帖子旁挂该站长的 rank 综合分/存活时长/坟场记录)。
**核心原则(两类评价共通):评价权必须由一次真实交互解锁**,否则信誉系统当天被刷穿。
- 特别防范:广场站长互为竞争对手,「任意互评」必被竞品刷差评当武器 → 所以必须「对接过才能评」。

## 10. SEO 策略

**分两类:架构性的必须建站期埋(后补=重做);内容性的可后期持续做。**

### 现在必须埋(架构性)
- Next.js SSR/SSG —— 页面可被收录(选 Next 的根本理由就是这个,匹配「靠搜索免费获客」的冷启动模型)。
- URL 永久结构 `/rank/{family}`、`/site/{slug}`、`/graveyard/{slug}` —— **一次定终身,收录后改动丢权重**。
- 每页动态 metadata(title/description)能力。
- JSON-LD 结构化数据:榜单=ItemList、评价=AggregateRating、坟场=客观措辞 → 搜索结果出富摘要,提点击率。
- sitemap.xml 自动生成(榜单+坟场优先收录)。

### 以后再做(内容性)
- 关键词布局、外链、导购长文(「2026 最便宜 Claude 中转站」)。

### 与权限的配合
- 详情页对游客部分可见 → 既保 SEO 入口,又留注册转化钩子。
- 广场刻意排除收录 → 保护底价。

## 11. 前端选型理由(已认可)

**Next.js(App Router)+ TS + Tailwind + shadcn/ui + Framer Motion + next-themes**

| 层 | 解决什么 | 理由 |
|---|---|---|
| Next.js | 「用户怎么找到你」 | SSR 让榜单/详情/坟场可被搜索收录;冷启动靠 SEO 免费获客。代价:比 SPA 复杂、需 Node 运行时 |
| Tailwind | 「你怎么快速打磨」 | 标签上直接写样式,迭代摩擦小 → 愿意打磨的次数多 → 成品更好 |
| shadcn/ui | 「界面怎么好看且是你自己的」 | 组件源码复制进项目,完全可控,默认就是 Linear/Vercel 那种现代审美;不是「别人的皮肤」 |
| Framer Motion | 微交互动效 | 榜单排名滑动、数字滚动、卡片 hover = 现代感来源 |
| next-themes | light/dark 双主题 | 记忆选择 + 跟随系统 + 防 SSR 白屏闪烁(FOUC) |

### 双主题强制约定(从第一个组件起)
- 所有颜色走 **shadcn 语义 CSS 变量**(`bg-background`/`text-foreground`/`primary`/`muted`/`border`),**禁止硬编码颜色**(不写 `bg-white`/hex)。双主题是「按规矩写」的自然结果。
- 默认跟随系统 `prefers-color-scheme`,用户切换后记住;切换按钮在全局 navbar;纯客户端切换,**不影响 SEO**。

- 不选 Ant/Element/MUI:自带强视觉风格,「一眼大厂后台」与「年轻化」冲突,且深层定制要跟框架打架。
- 不选 Vue/Nuxt:本身很好,但 shadcn/动效/招人生态当下 React 系更厚。
- 备选:若**完全不靠 SEO**(纯社群/私域导流),可换 Vite+React+Tailwind+shadcn,更轻更易部署。但榜单产品放弃 SEO 可惜,故默认 Next。
- 项目内有 `ui-ux-pro-max` 技能,搭前端时用它定具体视觉(配色/字体/组件样式)。

## 12. 底座项目背景

中转站本身由开源项目搭建,决定了「能探测什么」「能验证什么」。

- **new-api**(QuantumNous,github.com/QuantumNous/new-api):one-api 增强分支,**最主流搭建框架**。统一 OpenAI 格式网关,后台配多上游渠道、密钥池、负载均衡、计费、令牌额度。暴露 `/v1/chat/completions`、`/v1/models` 及后台 `/api/...`(站点信息/模型/用量)。
- **sub2api**(Wei-Shaw,github.com/Wei-Shaw/sub2api):把订阅制网页账号转成 API,账号池中转。

**对 Router-Hub 的意义:** 这些框架对外暴露标准化可探测面(`/v1/models`、`/v1/chat`、额度查询接口),使得:
1. 自动探测排名可行(存活/速度/可用性)。
2. C 端充值验证可复用 key 调额度接口,无需截图。

## 13. MVP 边界(明确不做)

### 一期做(两端最小闭环)
- 站长端:注册 → 上架站点 → 等审核 → 上线后看自己站探测数据 + 排名位置。
- 用户端:注册/匿名 → 看榜(分榜+排序筛选)→ 详情页 → 充值验证后评价。
- 平台:存活+质量分层探测 worker + 手动审核 admin 入口 + 坟场分级 + 新站观察区。
- 广场:结构化发帖 + 对接 + 互评(已验证站长)。

### 刻意不做(留后期)
- 真伪/降智检测(第三档,最强壁垒,留长期,先留数据位置)。
- 交易/担保/中间结算 —— **只做信息撮合,平台不碰钱**(资金合规风险归零)。
- 站长申诉机制 —— 改用「站长声明维护窗,窗内失败不计在线率」的被动缓冲,零客服成本。
- 站内私信、用户充值返利/积分、复杂标签体系、消息通知。

## 14. 关键决策速查(一栏回忆)

| 决策 | 结论 | 一句话理由 |
|---|---|---|
| 数据来源 | 平台主动探测 + 用户众测 | 客观为主、评价为辅 |
| 变现 | 一期只做撮合,不碰交易 | 资金/合规风险归零 |
| MVP 重心 | 两端最小闭环 | 验证整个模式 |
| 后端栈 | FastAPI + Tortoise ORM + Aerich + PostgreSQL + Redis | —— |
| 前端栈 | Next.js + Tailwind + shadcn + Framer Motion + next-themes | SEO + 现代 UI + 完全可控 + 双主题 |
| 探测 | 三层(存活/质量/触发) | 省钱与实时性平衡 |
| key | 站长自填,加密托管,只后端用 | 安全头等 |
| 评价资格 | C端充值key自证;B端对接confirmed | 真实交互才解锁,防刷穿 |
| 冷启动 | 方案 C 观察区 | 不污染主榜、防刷、给曝光 |
| 真实性 | MVP 只 0/1 | 降智检测留长期 |
| 坟场 | 分级状态机 + 客观措辞 | 防误伤、防法律风险、SEO 富矿 |
| 广场 | 结构化帖子 + 登录墙封闭 | 可筛选的市场,保护底价 |
| B端信誉 | 沿用 C 端 | 复用护城河,少维护一套表 |
| 权限 | 游客/user/owner(未验证/已验证) | 探测能力=广场准入门槛 |

## 15. 数据层约定(强制,所有表无例外)

| 约定 | 规则 | 理由 |
|---|---|---|
| ORM/迁移 | Tortoise ORM + Aerich(**不是 SQLAlchemy**) | Aerich 是 Tortoise 官方迁移工具 |
| 双键制 | 每表 `id`(bigint 自增,内部用不外暴露)+ `<实体>_id`(uuid7 业务键,唯一索引) | uuid7 有序,索引友好;业务键对外、主键对内 |
| 虚拟外键 | DB 层零外键约束;关联只存对方业务键值,完整性全在 service 层 | 解耦、便于分库分表/迁移、避免级联锁 |
| 假删除 | 全表 `is_deleted` + `deleted_at`;查询默认过滤 `is_deleted=false` | 数据可追溯,绝不物理删除 |
| 时间戳 | 全表 `created_at` + `updated_at` | —— |

**关联示例:** Goods 关联 User → Goods 表存 `user_id`(值=`User.user_id`),自身有 `goods_id`。所有 `xxx_id` 字段均建索引。所有 join / 级联 / 完整性检查在业务层做,数据库不设 FK。
